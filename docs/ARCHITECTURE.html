System Overview

The ARX Platform is a production-grade, research-lab-quality real-time computer vision system built on a strict four-layer architecture. Each layer runs as an independent process, communicates over well-defined IPC channels, and can be scaled, replaced, or debugged in isolation.

Shared Memory Layout (C++ ↔ Python)

[0..3]    Magic "ARX\0"
[4..7]    Protocol version (uint32)
[8..15]   Write sequence counter  ← C++ increments after writing a frame
[16..23]  Read sequence counter   ← Python increments after writing landmarks
[24..27]  Frame width  (uint32)
[28..31]  Frame height (uint32)
[32..35]  Frame stride (uint32, bytes/row)
[36..67]  FrameMeta (32 bytes, fixed)
[68 ..]   RGB pixels  (width × height × 3 bytes)
[68+P..]  Landmark JSON (64 KB, null-terminated UTF-8)

The two sequence counters provide a wait-free handshake with no mutex: the C++ engine writes a frame and bumps write_seq; Python detects the change, runs inference, writes landmark JSON, then bumps read_seq; C++ reads back when it sees read_seq ≠ write_seq.

04

C++ Vision Engine

Pipeline Stages

  • Stage 0 – Camera capture (per-camera thread, CPU affinity)
  • Stage 1 – Pre-process: resize to AI res, BGR→RGB
  • Stage 2 – SHM publish + landmark read-back
  • Stage 3 – AR compose: skeleton, face, cube, HUD
  • Stage 4 – Display via cv::imshow

Thread Safety

  • Lock-free RingBuffer<T,N> between every stage (power-of-2 size)
  • Atomic sequence counters for SHM handshake
  • No mutexes in the hot path
  • Drop policy: oldest frame dropped when queue full

Python AI / Gesture Layer

Gesture Classifier

  • Open hand – 4+ fingers extended
  • Closed fist – 0 extended + thumb tucked
  • Point up – index only, tip above MCP
  • V-sign – index + middle only
  • Pinch – thumb-tip ↔ index-tip < 25% of hand span
  • Swipe L/R – velocity > 1.2 u/s, horizontal dominant
  • Zoom / Rotate – two-hand dist / angle delta

1€ Smoothing Filter

Adaptive low-pass filter by Casiez et al. 2012:

  • Reduces jitter at rest (low cutoff)
  • Reduces lag during fast motion (high cutoff)
  • Applied independently to all 21×3 landmark components
  • Tunable: min_cutoff=1.5 Hz, β=0.01

GET /api/system/ping Liveness probe (returns ms timestamp)

WebSocket Fan-Out Design

The Hub maintains a goroutine-safe map of connected clients. Each client has a send chan []byte (capacity 256). Broadcast drains queued messages in a single WebSocket write frame. Slow clients are silently dropped (non-blocking send) — the pipeline is never back-pressured.

GPU Acceleration Notes

  • Build with -DENABLE_CUDA=ON to activate CUDA paths in OpenCV (e.g. cv::cuda::resize)
  • MediaPipe supports GPU delegate on Android/Linux via gpu_origin=MediaPipeTasksRunningModeGPU
  • For Jetson Nano/Orin: use cv::cuda::GpuMat for pre-processing, pass CPU copy to SHM only

cd arx-platform/cpp_vision_engine
cmake -B build -DCMAKE_BUILD_TYPE=Release -DENABLE_ZEROMQ=ON

cd arx-platform/python_ai_layer
python3 -m venv .venv && source .venv/bin/activate

python gesture_engine.py                      # reads from C++ SHM

Launch Order

The layers are independent processes, but the recommended start order is:

1. arx_vision_engine    (creates SHM, starts ZMQ PUB on 5556)
2. gesture_engine.py    (reads SHM, starts ZMQ PUB on 5557)
3. arx_control_plane    (SUB on 5556+5557, HTTP on 8080)
4. main_dashboard.py    (WS to localhost:8080)

Production & Scalability Notes

Horizontal Scaling

  • Run one C++ + Python pair per camera node
  • All nodes publish to a central Go cluster behind a ZMQ XSUB/XPUB proxy
  • Go control plane is stateless → scale behind a load balancer
  • WebSocket sessions are sticky (use nginx ip_hash)

Reliability

  • All drop policies are explicit (never block pipeline)
  • SHM version field allows hot rolling of Python AI layer
  • Go WS hub auto-evicts dead clients on ping timeout
  • Python FSM listeners are wrapped in try/except (never crash engine)

Observability

  • GET /api/telemetry/metrics exposes rolling averages
  • GET /api/system/health suitable for Prometheus scraping
  • Structured JSON logging via spdlog (C++) and zap (Go)
  • Per-pipeline drop counters surfaced in telemetry

Extension Points

  • Swap rule-based classifier for TFLite / TorchScript model in gesture_classifier.py
  • Add RTMP/HLS output in C++ Stage 4
  • Replace SHM with gRPC streaming for cross-machine deployment
  • Add Redis pub/sub in Go for distributed event bus
